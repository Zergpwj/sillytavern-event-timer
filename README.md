# 事件计时器 · Event Timer
给 AI 角色扮演加一条**真实走动的剧情时间轴**。
它做三件事：
1. **读时间** —— 从每轮 AI 正文里解析出「现在剧情里几点了」「这一轮过去了多久」；
2. **记事件** —— 把「需要经历一段时间才有结果的事」（赶路、疗伤、炼丹、等回信、计划实施……）登记成待办，算出预定完成时间；
3. **预定终点（现）提醒** —— 当剧情时间走到预定时间，把一条提醒注入到**下一轮**的提示词里，逼 AI 交代这件事的进展或结果，而不是无限期往后拖。
界面上有一个**常驻悬浮按钮**，直接显示当前剧情时间；点开可以看到全部进行中的事件、剩余时间、进度，以及每件事的**预期收益 / 风险 / 失败损失**。
> 主要面向 [SillyTavern（酒馆）](https://github.com/SillyTavern/SillyTavern)，但同时把核心引擎与宿主适配层拆开了，
> 所以同一套逻辑也能跑在别的 AI 角色扮演应用里（见 [移植到其它应用](docs/移植到其它应用.md)）。

## 安装（酒馆）
### 方式一：手动拷贝（推荐，最省事）
1. 找到酒馆的数据目录：
   - Windows 一般是 `C:\...\SillyTavern\data\<你的用户名>\extensions\`
   - 如果没有这个目录，就手动建一个
2. 把整个 **`event-timer`** 文件夹复制进去，变成：
   ```
   SillyTavern/data/<用户名>/extensions/event-timer/manifest.json
   SillyTavern/data/<用户名>/extensions/event-timer/index.js
   ...
   ```
3. 刷新酒馆页面（F5），进「扩展」（魔杖图标）→ 在 **「Installed Extensions（已安装扩展）」** 里
   应该能看到 **事件计时器 (Event Timer)**，确认它是启用状态。
4. 右侧出现一个常驻的悬浮按钮 `⏱ 第1天 08:00`，说明装好了。
### ⚠️ 放哪个目录，决定它出现在面板的哪一栏
这是最容易踩的坑，酒馆把三种目录分成两个区块显示（源码行为，跟是不是用 GitHub 装的无关）：
| 你把文件夹放在哪 | 酒馆识别的类型 | 出现在面板的 | 能从面板启停吗 |
| --- | --- | --- | --- |
| `data/<用户名>/extensions/` | `local` | **Installed Extensions（已安装扩展）** | ✅ 可以 |
| `public/scripts/extensions/third-party/` | `global` | **Installed Extensions（已安装扩展）** | ✅ 可以（需管理员） |
| `public/scripts/extensions/` | `system` | **Built-in Extensions（内置扩展）** | ❌ 不能，且标着「不可删除」 |
**所以如果你把文件夹丢进 `public/scripts/extensions/`，插件确实能生效，但它被归到「内置扩展」那一栏了**，
在「已安装扩展」里当然找不到。
想让它出现在「已安装扩展」（也就是所有 GitHub 安装的插件待的那一栏），把文件夹挪一步即可：
```
public/scripts/extensions/            ❌ 归到「内置扩展」
public/scripts/extensions/third-party/ ✅ 归到「已安装扩展」
```
扩展本体不用改任何代码——两种位置的加载 URL 都是 `/scripts/extensions/third-party/event-timer/`。
> 判据在酒馆源码里：`public/scripts/extensions.js` 里 `isExternal = name.startsWith('third-party')`，
> 然后 `const container = isExternal ? externalContainer : defaultContainer;`。
> 两个容器的标题分别是 `Installed Extensions:` 和 `Built-in Extensions:`。
### 方式二：用酒馆的扩展安装器
「扩展」→「Install extension」→ 填本仓库的 Git 地址 → 安装。
（需要仓库里 `manifest.json` 位于根目录，这一点已经满足。）
### 装好之后建议做的两件事
1. **加一段提示词**，让 AI 按标签协议输出。
   打开 [docs/给AI的提示词.md](docs/给AI的提示词.md)，把那段文字贴进**世界书**（推荐，关键词常驻）
   或者**角色卡的「备注/系统提示」**里。
   *（其实插件默认也会自动注入这段说明，但写在预设里更省 token、也更稳。）*
2. **导入一条正则**，把正文里的 `<计时器>…</计时器>` 区块从**显示**和**提示词**里都去掉
   （原始聊天记录不动，插件照样能解析）。
   文件：[正则-隐藏计时器标签.json](正则-隐藏计时器标签.json)
   —— 它是和插件一起打包的那份的副本，正本在
   `event-timer/regex/隐藏计时器标签块.json`，两处内容相同。
   导入路径：酒馆 → 扩展 → 正则 → **导入** → 选这个文件。
   只有一条规则，同时勾了 `Only Format Display` 和 `Only Format Prompt`
   ——为什么这样等价于两条规则、以及为什么千万别两个都不勾，见
   [docs/正则-隐藏计时器标签.md](docs/正则-隐藏计时器标签.md)。

## 快速上手
装好之后直接正常聊天即可。AI 只要在回复末尾带上这样的区块：
```
<timer>
时间: 第3天 14:30
事件+: 熬制解毒药   6小时   预期=伤势好转；失败则药材全废   变数=火候、巡逻队   资源=药材三份
</timer>
```
插件就会：
- 把剧情时钟拨到 **第3天 14:30**；
- 登记事件《熬制解毒药》，预定 **第3天 20:00** 完成；
- 悬浮按钮上出现 `1` 的角标，点开能看到倒计时、进度条、预期 / 变数 / 资源。
之后这件事会依次经过四个时点（默认设置下）：
| 时点 | 插件做什么 |
| --- | --- |
| 定期检查（**每 N 天一个**，默认 7 天） | 静默问一次：这期间外面的变化牵扯到它了吗？需要就改参数 |
| 即将结束（当前总时长的 85%） | 静默让 AI 列一份「到预定终点要交代什么」的要点 |
| 预定终点（现）（当前到期时间） | 往提示词里塞提醒，让 AI 在正文里交代结果 |
| 预定终点（旧） | 只有事件被**延长**过才存在 —— 旧到期时间到了但它还没结束 |
> **定期检查是一串点位，不是时间轴上的一个刻度。**
>
> 从**事件开始**算起、每 N 天一个，位置**固定不变**：事件被延长时只在尾部接着往下排，
> 已有的点位日期一个都不动。所以「事情拖得越久，回头看它的次数越多」。
>
> 定期检查点位不会落在「即将结束」之后（那是它的活）；事件比 N 天还短时退到正中间一次。
> 一次跨过好几个点位时有报最靠后的那个 —— 事后补发一条「你已经到 21% 了」没有意义。
>
> 想看某个事件的具体点位：悬浮面板 → 展开事件卡片的「时刻表」。
预定终点（现）时的注入长这样：
```
[timer·预定终点（现）]
当前剧情时间：第3天 20:10
下列事件已经到达预定的完成时间，请在正文里交代它们的结果：
1. 《熬制解毒药》 预定完成时间：第3天 20:00（已超时 10分钟）
   预期：伤势好转；失败则药材全废
   变数：火候、巡逻队
   总时长：6小时
（交代完就够了，不需要写结束标记，计时器会自己收掉这件事。）
[结束]
```
这段文字**不会出现在聊天记录里**（走的是酒馆的 `setExtensionPrompt`，以旁白身份按深度插入），
所以你不会看到它，但 AI 会看到。
**关键：AI 不需要跟踪事件、不需要写结束标记。** 它每轮只报时间戳，事件开始时登记一次，
之后等插件提醒。详见 [docs/提醒时点.md](docs/提醒时点.md)。
> **标签名默认是 ASCII 的 `<timer>`** —— 模型生成更稳，不会被中文的全角/简繁问题搞坏。
> `计时器` / `story_timer` / `storytimer` / `STIMER` 也照样解析，不用改老对话。
> 想换回中文标签，把设置里「标签名」的第一个改成 `计时器` 即可。
### 没有标签也能用
AI 不肯按格式输出时，正则兜底会自动顶上：
| 正文里写了 | 插件的理解 |
| --- | --- |
| `三天后，他回到了城里。`（在句首） | 时间轴往前跳 3 天 |
| `他需要三天时间才能炼好这炉丹药。` | 新建事件，3 天后到期 |
| `他花了三天才炼好。` | 已经发生过的，不登记 |
| `……第二天清晨，……` | 时钟走到第 2 天早上 6 点 |
| ``三天后，他回到了城里。`` | 时钟前进 3 天（正文里的**时长**表达） |
> 插件**不从正文猜日期**。「第二天清晨」这类跨天信息要么由 AI 写进标签的 `时间:`，
> 要么你自己用面板的 `+1天` 拨。以前那两个「从正文读日期 / 用 LLM 抽取」的开关都已删除 ——
> 让插件替 AI 编时间，猜错了不会报错，只会让时钟以看似合理的速度偏移。

## 时间基准：计数制 vs 日历制
插件支持两种时间轴，设置里一键切换。
### 计数制（默认）—— 第 N 天
适合没有历法的世界，或者你不想让 AI 操心日期的时候。
```
时间: 第3天 14:30
```
### 日历制 —— 年月日
**大多数世界观其实用的是这个。** 打开「设置 → 时间基准 → 时间制式 → 日历制」即可。
```
时间: 1247年3月15日 14:30
流逝: 3天
事件+: 加急送信到北境   12天   收益=援军提前抵达   风险=信使被截杀   损失=北境孤立无援
```
日历制下会额外支持：
| 能力 | 说明 |
| --- | --- |
| 真实年月日解析 | `1247年3月15日` / `1247-03-15` / `1247/3/15` / `3月15日` / `1247年` 都能认 |
| 相对日期词 | `明天` `后天` `昨天` `次日` `明年` `下个月` `这个月` |
| 纪元前缀 | 可配 `帝国历`，显示成 `帝国历1247年3月15日` |
| **日历精确的月/年加法** | 「一个月后」按真实月份推进：1月31日 + 1个月 = 2月28日（闰年 2月29日），**不是**固定 30 天 |
| **自定义月名（参与解析）** | 配好之后 AI 可以直接写「霜月7日」，不用写数字月份 |
| 自定义历法 | 每月天数随便填（12 个月 × 30 天、13 个月、四季各 3 月……），闰年规则也能改 |
| 自定义显示格式 | `{era} {year} {month} {monthName} {day} {daySuffix}` 出日期，`{hour} {minute} {time}` 出时间；写了时间就不会再重复追加 |
| **AI 推断历法** | 按世界书 / 角色卡 / 对话线索，让模型填出纪元、月名、闰年规则和当前日期 |
日历制的设置项（设置面板 → 时间基准）：
```
时间制式     日历制：年月日（1247年3月15日，更常见）
历法预设     公历（可推真实年月日，带闰年） / 简化历（12 个月 × 30 天，无闰年） / 完全自定义
起始日期     1247-03-15 08:00
纪元前缀     帝国历            ← 留空则有显示「1247年3月15日」
每年月数     12                ← 一年不一定是 12 个月；改了之后每月天数和月名一起跟着变
每月天数     31,28,31,30,31,30,31,31,30,31,30,31
             也可以有填一个数（例：30）= 每个月都一样
闰年规则     4 / 100 / 400 / 2  ← 每4年一次，跳过100的倍数，但400的倍数仍算，闰日加在2月
日期格式     {era}{year}年{month}月{day}日
自定义月名   [编辑月名…]        ← 逐月填写或批量导入；配好后 AI 可以直接写「春月」
```
> **预设有负责「起点」**：每月天数、闰年、日期格式。你手动改过的字段优先。
> 选「完全自定义」= 就停在**现在这套**上继续改（不会跳回公历）。
> 月名任何时候都不会被切预设冲掉。
>
> 切换制式时插件会自动重置一次起始时间并重算，不需要额外点什么。
日历制下提醒文本长这样：
```
[计时器·剧情时间提醒]
当前剧情时间：1247年3月15日 20:10
以下事件已经到达预定的时间点，本轮正文必须交代它们的进展或结果，不得跳过、不得推迟：
1. · 《熬制解毒药》 预定完成时间：1247年3月15日 16:00（已超时 4小时10分钟）
   · 预期收益：伤势好转
   ...
```

## 配置档案：换角色卡不再失效
每个角色卡 / 群聊可以**绑定一份配置档案**，切换对话时自动套用。
没绑定任何档案的角色卡，统一使用内置的 **「全局默认」**。
```
配置档案（按角色卡自动切换）
当前角色：爱丽丝
当前生效：爱丽丝的世界
当前配置 [ 爱丽丝的世界 ▾ ]
[为当前角色新建档案] [绑定当前角色到本档案] [解绑当前角色] [重命名…] [删除]
```
推荐流程：打开角色卡 → 把时间制式 / 历法 / 提示词调好 → 点「为当前角色新建档案」。
绑定用的键是**稳定标识**（`char:<角色卡文件名>` / `group:<群聊 id>`），不是角色名。
档案有存设置；**进行中的事件与剧情时钟仍然跟着聊天记录走**，两者互不干扰。
> ⚠ 停在「全局默认」上改设置，改的就是全局默认本身（所有未绑定角色都受影响）。
> 设置面板在你处于这个状态、且当前有角色卡时会给出橙色提示。

## 提示词库：注入的文案可以改、可以存、可以改名、可以分享
```
提示词库
[ 默认提示词（内置） ▾ ]
[编辑] [另存为…] [重命名…] [删除] [新建空白] [导出…] [导入…]
```
- 内置那份叫 **「默认提示词」**，内容留空 = 用程序生成的内置文案；
- **编辑** → 改「记录格式说明」和「提醒模板」，里面可以用
  `{{tag}} {{exampleClock}} {{timeMode}} {{era}} {{monthNames}} {{protocol}} {{header}}` 等占位符；
- **另存为…** 复制一份改，原件不动；**重命名 / 删除** 对你自己的副本可用；
- 「默认提示词」不能改名也不能删，避免把自己搞丢；
- 编辑器里有「填入当前内置文案（可再改）」按钮，可以在内置文案基础上改，不用从零写。

老版本的 `reminder.protocolTemplate` 会在首次启动时**自动迁移**成一条
「我的提示词（从旧设置迁移）」，不会丢。

### 导出 / 导入：把调好的文案分享给别人

**导出…** 把当前这条打包成一份 JSON —— 三条出路：

1. **下载文件**（浏览器允许时最省事）
2. **复制到剪贴板**
3. 手动全选复制（前两条被浏览器挡住时的兜底，框里的文本一直摆着）

**导入…** 从文件选，或者直接把 JSON 粘进框里。格式长这样：

```json
{
  "format": "event-timer-prompt",
  "version": 1,
  "name": "硬核生存向",
  "protocol": "……记录格式说明……",
  "mid": "……定期检查文案……",
  "late": "……即将结束文案……",
  "origin": "……预定终点（旧）文案……",
  "due": "……预定终点（现）文案……"
}
```

几条规则：

- **导入永远是「新增一条」**，不会覆盖你现有的任何一条 —— 即使名字撞了也照加，
  让你看得见重名、自己决定删哪个。导入后会自动切过去用；
- `format` 对不上就拒绝（挡住拖错文件）；`version` 比当前新也拒绝；
- **手写的 JSON 也认**（没有 `format` 会提醒一句，但只要有一段文案就能导入）；
- `due` 认老名字 `reminder`，老文件也能导；
- 单字段超过 20000 字符会截断并提醒，避免导入一个超大文件把设置撑爆；
- 导出的 JSON **不含 `id`** —— id 是本地的，带出去只会和别人的撞。

## AI 推断历法
设置面板 → 时间基准 → **AI 推断历法**
按勾选的来源（**世界书条目 / 角色卡设定 / 最近对话 / 用户人设**）收集线索，
让模型判断这个世界用什么历法、当前是什么时间，给出预览后由你确认套用。
| 后端 | 说明 |
| --- | --- |
| **酒馆主 API** | 走 `generateQuietPrompt`，不写聊天记录、不触发世界书扫描 |
| **自定义 API** | 自己填 Base URL / API Key / 模型名，走 OpenAI 兼容接口（也适用于非酒馆宿主） |
出于安全考虑，世界书线索**默认只读当前聊天绑定和角色卡绑定的那几本**，
不会去翻整个世界书目录。推断只读不写，且只在你点「开始推断」时才发请求。
细节与返回的 JSON 形状见 [docs/配置档案与提示词库.md](docs/配置档案与提示词库.md)。

### 界面语言
插件带一份英文界面。酒馆切到英文时，计时器的面板和弹窗会自动跟着切
（`manifest.json` 里声明了 `i18n`）。
**注入给 AI 的文案（协议 / 提醒）不跟着切** —— 那是给模型读的，
四个时点的文案都可以在「提示词库 → 编辑」里逐条改成你想要的任何语言。
### 注入的内容在哪里看
隐形注入本身是看不见的（走 `setExtensionPrompt`，不进聊天记录）。
所以插件把它**如实折叠进消息里**，跟模型的思考块一个道理 —— 对称的两半：
| 挂在哪 | 显示什么 | 颜色 |
| --- | --- | --- |
| **用户消息** | **发给模型的东西**（这一轮注入进提示词的全部内容） | 蓝 |
| **AI 消息** | **模型发出来的东西** —— 它写的 `<timer>` 标签区块原文 | 绿 |
标签区块平时被酒馆正则从显示里藏掉了（见 [正则那节](#2-导入一条正则)）——
**藏起来是为了不碍眼，折叠起来是为了随时能查**。两者不冲突。
摘要分两种：
```
▸ 发给模型 · ×1（定期检查）                        ← 这一轮带了提醒
▸ 发给模型 · 仅记录格式说明（307 字符）          ← 这一轮只有协议说明
```
**为什么要专门标出第二种**：协议说明（教 AI 用标签的那段）默认**每轮都在发**。
如果只在有提醒时才显示，「没有块」就会被误读成「插件什么都没注入」——
而实际上模型每轮都收到了那 300 多字符。现在没有块只有一种含义：
**这一轮真的什么都没注入**（比如你把协议说明挪进了世界书，并关掉了
`提醒内容 → 注入协议说明`）。
> 挂载点说明：注入是在**生成前**那一刻交付的。而酒馆触发这个钩子时
> （`script.js:4262`），你的发言**还没进聊天**（`script.js:4394` 才入栈）——
> 所以插件不能在那一刻去找"最近一条用户消息"，否则整整错一楼。
> 实际认领发生在 **AI 回复到达时**，那时你的发言已经在聊天里了。
在 **界面** 分组里可以关掉。
### 关于「可见模式」
你提到隐藏可以靠酒馆正则实现。除此之外插件也提供可见模式：
- **隐形注入**（默认）——走 `setExtensionPrompt`，聊天记录里看不到；
- **可见：填进输入框** —— 把提醒文本追加到输入框，你可以改、可以删，确认后再发出去；
- **两者都做** —— 既隐形注入，也填一份到输入框留底。

## 对外 API
任何扩展、脚本、或其它应用都可以通过 `window.StoryTimer` 调用：
```js
StoryTimer.clock              // { day: 3, minute: 1210 }
StoryTimer.events             // 面板用的快照（active / due / finished）
StoryTimer.injection          // 最近一次注入的文本
StoryTimer.observe('正文……')  // 手动喂一段 AI 正文
StoryTimer.inject()           // 取本轮注入文本（不记账）
StoryTimer.commit()           // 取本轮注入文本并记为「已提醒」
StoryTimer.advance(60, '手动') // 推进 60 分钟
StoryTimer.addEvent({ title: '等待回信', durationMinutes: 2880, reward: '…' })
StoryTimer.resolveEvent(id, '结果')
StoryTimer.on(fn)             // 订阅状态变化
```

## 设计要点（为什么这么做）
**有用 `SillyTavern.getContext()`，不 import 酒馆源码。**
酒馆自 1.12 起把对外接口挂在 `globalThis.SillyTavern = { libs, getContext }`。
网上很多扩展写 `import { ... } from '../../../../script.js'`，一旦酒馆调整目录层级就全废。
本插件只走官方 context，并在 `host/bridge.js` 里做了能力探测，拿不到就降级而不是报错。
**状态是「重放」出来的，不是「累积」出来的。**
引擎的事件 id 由「标题 + 到期绝对分钟」哈希得到，因此同一段聊天记录重放必然得到同一个状态。
用户的所有手动干预（加事件、删事件、改字段、推进时间）都记在 `overlays` 里，重放结束后再套用。
好处：改历史消息、换 swipe、删消息之后点一次「重算」，状态立刻正确，而手动加的事件不会丢。
**注入用扩展提示词，不改聊天记录。**
`setExtensionPrompt(key, text, IN_CHAT, 0, scan, role)` 会在**拼装提示词时**以旁白身份插入到指定深度，
聊天界面上完全看不到，也不会污染你的输入。这比直接改 `chat` 数组安全得多。
**聊天数据存在 `chatMetadata` 里。**
跟着聊天记录走：换聊天自动换状态，导出聊天时数据一起走，删除聊天时一起没。
更详细的酒馆 API 事实（都在真实源码里核对过）见 [docs/酒馆接入笔记.md](docs/酒馆接入笔记.md)。

## 常见问题
**Q：AI 完全不按标签格式输出怎么办？**
先确认设置里「解析方式 → 标签协议」「正则兜底」都开着，然后：
把 [docs/给AI的提示词.md](docs/给AI的提示词.md) 贴进世界书（不要只靠插件自动注入，
世界书的内容在主提示词里的权重通常更高）；插件不会替你猜时间 —— 它只认标签和正文里明确的**时长**表达。
**Q：悬浮按钮不见了。**
设置里检查「界面 → 显示常驻悬浮按钮」；也可能是拖到了屏幕外面，
点设置里的「把悬浮按钮复位到右下角」。
**Q：时间轴跑飞了。**
多半是正则兜底把某段回忆当成了时间跳跃。设置里把「解析方式 → 没有标签时用正则扫正文兜底」关掉，
有信任标签里的 `时间:`；然后点「重算」。
**Q：提醒太啰嗦 / AI 不理。**
把「提醒方式」改成「只在预定终点（现）时提醒一次」，事件就只会提醒一遍。
如果反而是 AI 经常无视提醒，改成「自定义时点」并勾上「预定终点（现）之后每轮都提醒」。
提醒太频繁反而会让模型忽略它。
**Q：AI 需要一直记着我交代的事件吗？**
不需要。AI 每轮只报时间戳，事件开始时报一次信息，之后完全不用管 ——
什么时候该问由插件决定，交代完了插件会自己归档。
**Q：token 消耗大吗？**
默认状态下插件**不额外发请求**，注入的文本随到期事件产生，通常几十到两三百 token。
插件从不额外发请求（LLM 抽取那个功能已经删掉了）。
**Q：会影响别的扩展吗？**
所有 DOM 选择器都带 `st-timer` 前缀，所有全局变量只有 `window.StoryTimer` 和
`chatMetadata.story_timer` / `extension_settings.story_timer` 三个命名空间。
