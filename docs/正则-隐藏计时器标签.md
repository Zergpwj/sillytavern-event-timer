# 正则：隐藏正文里的 `<计时器>` 标签块

## 文件在哪

**同一份内容，两个位置**（`tools/verify-regex.mjs` 会检查它们是否一致，改一个必须同步另一个）：

```
① 跟插件一起打包的正本
   <扩展目录>/regex/隐藏计时器标签块.json
   例如装在 third-party 就是：
   <酒馆>/public/scripts/extensions/third-party/event-timer/regex/隐藏计时器标签块.json
   从 GitHub 装的则是：
   <酒馆>/data/<你的用户名>/extensions/sillytavern-event-timer/regex/隐藏计时器标签块.json

② 项目根目录的副本（方便直接点选导入）
   <项目根>/正则-隐藏计时器标签.json
```

两个都不在插件的加载路径上 —— 酒馆只读 `manifest.json` 里声明的 `js` / `css`，
多出来的 `regex/` 文件夹会被忽略，不影响插件运行。

## 怎么导入

1. 酒馆 → 扩展（魔杖图标）→ **正则**
2. 点 **导入**
3. 选上面的 JSON 文件
4. 选导入目标：**Global（全局）**（所有角色生效）或 **Scoped（局部）**（只对当前角色）
5. 如果当前聊天没变化，左右切换一下角色再切回来

## 文件里只有一条规则

```json
{
  "scriptName": "事件计时器：隐藏标签块（显示 + 提示词）",
  "placement": [2],
  "markdownOnly": true,
  "promptOnly": true
}
```

查找正则：

```
/\s*<(?:timer|计时器|story_timer|storytimer|STIMER)>[\s\S]*?<\/(?:timer|计时器|story_timer|storytimer|STIMER)>\s*/gi
```

替换成 `\n`。

---

## 关于那两个勾选框（重要）

酒馆里这两个勾选框叫 **Only Format Display**（`markdownOnly`）和
**Only Format Prompt**（`promptOnly`）。它们的判定逻辑是**或（OR）**，不是与（AND）：

```js
// public/scripts/extensions/regex/engine.js:347
allRegex.forEach((script) => {
    if (
        (script.markdownOnly && isMarkdown) ||              // ① 勾了「显示」且当前在渲染显示
        (script.promptOnly && isPrompt) ||                  // ② 勾了「提示词」且当前在拼提示词
        (!script.markdownOnly && !script.promptOnly && !isMarkdown && !isPrompt)  // ③ 两个都没勾
    ) {
        // 执行替换
    }
});
```

由此得出三种模式：

| 勾选情况 | 实际作用范围 | 说明 |
| --- | --- | --- |
| 只勾 **Display** | 只在渲染聊天界面时 | 界面看不到标签，但标签仍然发给 AI |
| 只勾 **Prompt** | 只在拼提示词时 | AI 看不到标签，但界面上仍然显示 |
| **两个都勾** | 显示 **和** 提示词 | 两边都看不到 —— **本文件用的就是这个** |
| 两个都**不**勾 | `!isMarkdown && !isPrompt`，也就是**源文本**路径 | ⚠️ 会**永久删掉聊天记录里的标签**，插件就没法解析了 |

### 所以：一条规则勾两个框 = 两条规则各勾一个

原来的版本用了两条规则（一条只勾 Display、一条只勾 Prompt）。因为判定是 **OR**，
一条规则同时勾两个框会命中 `markdownOnly && isMarkdown` **或** `promptOnly && isPrompt`，
效果和两条规则完全一样。所以现在合并成了一条。

> 验证脚本 `tools/verify-regex.mjs` 会复刻这段判定逻辑，直接打印出每条规则作用于哪几条路径。

### ⚠️ 千万不要两个都不勾

`script.js:6422` 在把 AI 回复**存进聊天记录之前**会调用一次不带标记的 `getRegexedString`：

```js
// Regex uses vars, so add before formatting
getMessage = getRegexedString(getMessage, isImpersonate ? USER_INPUT : AI_OUTPUT);
```

这时 `isMarkdown` 和 `isPrompt` 都是 `undefined`，于是命中上表的第三种模式 ——
标签会被**真的从消息里删掉**，插件读 `message.mes` 时就读不到了，计时器直接失效。

### 要不要勾 Prompt？

勾上「提示词」有两个效果，一好一坏：

- 👍 **省 token** —— 每条历史消息里的标签块通常几十到几百 token，长对话下很可观
- 👎 **少了一个"以身作则"的示范** —— AI 在上下文里看到自己之前写对过的标签格式，
  对格式遵守度有帮助

因为插件每轮都会注入一次格式说明，
格式规范本来就一直在，所以本文件默认勾上以省 token。

**如果你发现 AI 越来越不爱写标签**，把这条规则的 **Only Format Prompt** 取消勾选，
让历史标签保留在上下文里当范例，通常会有改善。

## 改了标签名怎么办

如果你在插件设置里把「标签名」改成了别的（比如 `沙漏`），用编辑器打开这个 JSON，
把正则里的那几个名字替换掉：

```
/\s*<沙漏>[\s\S]*?<\/沙漏>\s*/gi
```

或者不改文件，直接在酒馆的正则编辑器里改。

## 为什么不干脆让插件把标签删掉

因为「删掉」和「不显示」是两件事：

- 插件需要**读**原始文本（`message.mes`）才能解析，删了就没法解析；
- 酒馆的正则只在**渲染**和**拼提示词**时做替换，原始记录不受影响 —— 这正是要的行为。

另外正则方案对你是**透明可撤销**的：不想要了把规则禁用就行，
不会出现「插件偷偷改了聊天记录」这种不可控的情况。

> 插件设置里原本有个「复制正则」按钮，已经按你的要求移除了，现在只提供这个文件。
