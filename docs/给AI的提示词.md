# 给 AI 的提示词（标签协议）

这段文字是整套机制的**关键**：它让 AI 在每次回复的末尾附上一小块机器可读的数据，
插件才能准确知道「现在几点」「有什么事情正在等待」。

把它放进下面任意一个位置（按推荐度排序）：

1. **世界书（World Info / Lorebook）条目** —— 推荐。
   关键词填 `timer, 时间, 事件`，内容粘贴下面整段，位置设为 `↑Char` 或 `↓Char`，常驻（蓝灯）。
2. **角色的「备注 / 系统提示」**（Character Note / System Prompt）。
3. **预设里的系统提示词**（对所有角色生效）。

> 插件本身也会自动注入这段说明（设置里「提醒内容 → 自动教 AI 使用标签协议」默认开启）。
> 两边同时开着不会冲突 —— 内容是一样的。
>
> **但如果你把这段写进世界书，建议把插件里的自动注入关掉**，省一份 token。

---

## 核心设计：AI 不需要跟踪事件

这是整套设计里最重要的一条。AI 只做三件事：

1. **每轮报时间戳**（唯一的硬性要求）
2. **事件开始时登记一次**（名字 / 时长 / 预期 / 变数 / 资源）
3. **收到提醒时回应**（在正文里交代结果，或者按要求调整参数）

**之后就不用再向计时器汇报了。** 不要主动报进度，不要写结束标记。
什么时候问、问什么，由计时器决定。

## 直接复制这一段（计数制）

```
[timer·记录格式]
请在每次回复的末尾追加一个 <timer> 区块，用来同步剧情时间与「需要经历一段时间才有结果」的事件。正文里不要提到这个区块。

<timer>
时间: <本轮结束时的剧情时间>          ← 必填，每轮都要写
事件+: 名字 | 时长 | 预期=… | 变数=… | 资源=…
</timer>

规则：
1. 「时间」是唯一必须写的字段，写成「第N天 HH:MM」这样的完整绝对时间。
2. 「事件+」只写需要时间才有结果的事（赶路、疗伤、炼丹、等待回信……），立刻见效的事不要写。
3. 「事件+」只在开始时写一次就够了，之后不用再向计时器汇报：不要写进度，也不要写结束标记。
   计时器会在后续时间点提醒你，届时按提醒里的要求回应即可。
4. 提醒里要求你调整时，用「事件~: 名字 | 时长=… | 到期=… | 预期=… | 变数=… | 资源=… | 要点=…」回应。
5. 时长写法：3天 / 6小时 / 半小时 / 一炷香 / 一个月；也可以直接写「到期: 第5天 09:00」。
```

## 日历制（年月日）版本 —— 更常用

绝大多数世界观用的是真实年月日，而不是「第几天」。把插件设置里的
**时间基准 → 时间制式** 切成 **日历制**，然后用下面这段：

```
[timer·记录格式]
请在每次回复的末尾追加一个 <timer> 区块，用来同步剧情时间与「需要经历一段时间才有结果」的事件。正文里不要提到这个区块。

<timer>
时间: <本轮结束时的剧情时间>          ← 必填，写成完整的年月日，例如 1247年3月15日 14:30
事件+: 名字 | 时长 | 预期=… | 变数=… | 资源=…
</timer>

规则：
1. 「时间」是唯一必须写的字段，每轮都要写，写完整的绝对日期。
2. 「事件+」只写需要时间才有结果的事，立刻见效的事不要写。
3. 「事件+」只在开始时写一次就够了，之后不用再向计时器汇报：不要写进度，也不要写结束标记。
   计时器会在后续时间点提醒你，届时按提醒里的要求回应即可。
4. 提醒里要求你调整时，用「事件~: 名字 | 时长=… | 到期=… | 预期=… | 变数=… | 资源=… | 要点=…」回应。
5. 时长写法：3天 / 6小时 / 一个月；也可以直接写「到期: 1247年4月1日 09:00」。
```

## 字段说明

### 必填

| 字段 | 说明 |
| --- | --- |
| `时间` | 本轮**结束**时的剧情内时间。写绝对值，不要写「过了一会儿」。**这是唯一必须写的字段。** |

### 事件登记（`事件+`，只在事件刚开始时写一次）

```
事件+: 派商队收粮 | 1个月 | 预期=带回过冬的粮食，若粮价大涨则数量减半 | 变数=粮价、敌对领主是否封路、返程路况 | 资源=本金500两，商队30人
```

| 字段 | 含义 |
| --- | --- |
| 名字 | 事件名。后面所有更新都靠它匹配 |
| 时长 | 要做多久，或者用 `到期=` 给绝对时间 |
| `预期=` | 你期待它变成什么样。**成功、失败、条件都写在这一句里** |
| `变数=` | 什么会让它偏离预期。不限内外、不限正负 |
| `资源=` | 持续性的资源收支（建造、贸易这类任务用）。**插件不解析它**，只是原样回显，帮你记住 |
| `详情=` | 场景补充说明 |

> `资源=` 以前叫 `账目=`。**旧写法仍然完全有效** —— 老聊天里 AI 写的 `账目=`
> 照样能解析，两个都写时以 `资源=` 为准。只是以后教给 AI 的是新名字。

> **为什么是「预期 + 变数」，而不是「收益 / 风险 / 损失」？**
> 后三个格子只适合"任务型"事件。等师父回信、打盹、修炼突破这类事
> 塞不进"奖励 / 风险 / 代价"的框架，模型只能硬凑，凑出来的文本又会被注入回去误导它自己。
> 两个自由字段能覆盖各种情况，而且 `变数=` 正好对应定期检查要问的问题：
> 「外面的变化牵扯到它了吗？」
>
> 老写法仍然兼容：只写 `收益=` / `风险=` / `损失=` 的话，插件会自动折叠成「预期」和「变数」。

### 可选

- 立刻见效的事**不要**写成事件（说一句话、拔剑、转身）。
- 太短的事插件会忽略（默认门槛 6 小时，可调）。

## 会被提醒的四个时点

| 时点 | 它会问你什么 | 你要写进正文吗 |
| --- | --- | --- |
| 定期检查 | 世界变了没有？要改时长 / 预期吗？ | ❌ 不用 |
| 即将结束 | 列出「到点要交代哪几个方面」 | ❌ 不用（写在 `<timer>` 区块里） |
| 预定终点（旧） | 过了原定时间还没结束 —— 让这件事在剧情里有体现 | ✅ 要 |
| 预定终点（现） | 交代最终结果 | ✅ 要 |

详细说明见 [提醒时点.md](提醒时点.md)。

## 调整事件（`事件~`）

只在**计时器提醒你**的时候才需要写：

```
事件~: 派商队收粮 | 时长=20天
事件~: 派商队收粮 | 到期=1247年4月1日 09:00
事件~: 派商队收粮 | 预期=粮价上涨导致收粮减少，但返程提前
事件~: 派商队收粮 | 变数=粮价、返程路况
事件~: 派商队收粮 | 资源=现存石料500方，每月消耗200方
事件~: 派商队收粮 | 要点=是否按时到 / 带回多少粮 / 有没有折损
```

> ⚠️ `时长=` 指的是**从事件开始算的总时长**，不是「再加多久」。
> 想表达「还要再两天」，请用 `到期=<新的绝对时间>`。

## 常见问题

**Q：AI 不写这个区块怎么办？**
先确认世界书条目真的被触发了（关键词要能命中）。再确认「时间」那一行没有用相对说法。

**Q：AI 写成了 `<计时器>` 而不是 `<timer>`？**
没关系，两个都认。默认教它写 `<timer>`（ASCII 更稳），但解析器支持
`timer` / `计时器` / `story_timer` / `storytimer` / `STIMER` 五种。

**Q：`时间` 那一行它总照抄示例？**
插件注入的协议里**故意不写具体示例值**（只写占位符 + 当前时间作参照），
就是为了防这个。如果你自己写世界书，也请照做 —— 别写 `时间: 第3天 14:30`，
写 `时间: <本轮结束时的剧情时间>`。
