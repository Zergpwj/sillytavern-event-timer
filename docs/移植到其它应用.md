# 移植到其它 AI 角色扮演应用

整套代码是刻意分成两半的：

```
core/   纯逻辑：时间模型、词法、解析、调度、提醒文本     ← 完全不知道「宿主」的存在
host/   宿主适配：读写消息、持久化、注入、提示           ← 每个应用写一份
ui/     界面：悬浮按钮、面板、设置                       ← 只依赖 DOM 和 app
app.js  装配：把上面三者接起来（也不认识酒馆）
```

要接入一个新应用，**只需要写一个 host 适配器**，其它一行都不用改。

---

## 一、host 需要实现的接口

```js
{
    kind: 'myapp',                     // 唯一标识
    label: '我的应用',                  // 界面上显示的名字

    capabilities: {                     // 能力声明（界面据此做降级）
        injection: true,                //   能不能自动往提示词里注入
        chatMetadata: true,             //   有没有「跟随聊天」的存档位置
        extensionSettings: true,        //   有没有全局设置存档
        events: true,                   //   能不能推事件
        prefillInput: true,             //   能不能写输入框
        quietPrompt: false,             //   能不能发静默请求
        slashCommands: false,
    },

    // ── 生命周期 ──
    ready(): boolean,
    attach(): void,                     // 注册事件监听
    detach(): void,

    // ── 事件 ──
    onEvent(type, handler): () => void, // 返回取消订阅函数

    // ── 持久化 ──
    loadSettings(): object | null,
    saveSettings(settings): boolean,
    loadChatState(): object | null,
    saveChatState(state): boolean,
    getChatId(): string | null,

    // ── 聊天内容 ──
    getChatMessages(): Array<{ index, text, isUser, isSystem, name }>,

    // ── 注入 ──
    setInjection(text, { position, depth, role, scan }): boolean,
    clearInjection(): boolean,
    getInjection(): string,

    // ── 输入框 ──
    getInputText(): string,
    setInputText(text): boolean,
    appendToInput(text): boolean,
    focusInput(): void,

    // ── 提示 ──
    toast(message, type): void,

    // ── 可选 ──
    quietPrompt(prompt, { responseLength }): Promise<string>,
    getSettingsContainer(): HTMLElement | null,
}
```

### 需要派发的事件类型

| 事件名 | 时机 | payload |
| --- | --- | --- |
| `chat-changed` | 切换 / 新建 / 载入聊天 | 任意（本项目只用它作为信号） |
| `message-received` | AI 产生了一条新正文 | `{ args: [消息下标] }` |
| `message-sent` | 用户发送了消息 | 同上 |
| `message-edited` | 某条消息被编辑 | — |
| `message-deleted` | 消息被删除 | — |
| `message-swiped` | 换了 swipe | — |
| `before-generation` | 即将开始生成（用来刷新注入） | — |

最省事的做法：**只实现 `message-received` + `chat-changed`**。
其它事件缺失时，App 只是不会自动重算，用户可以手动点「重算」。

## 二、最小可用适配器（约 40 行）

假设你的应用有一个全局对象 `MyApp`，能拿到消息列表、能写存档、能拿到输入框：

```js
import { createGenericHost } from '../event-timer/host/generic.js';

export function createMyAppHost() {
    const listeners = new Map();
    const emit = (type, payload) => {
        for (const fn of [...(listeners.get(type) ?? [])]) fn(payload);
    };

    return {
        kind: 'myapp',
        label: '我的应用',
        capabilities: { injection: false, chatMetadata: false, events: true, prefillInput: true },

        ready: () => !!globalThis.MyApp,
        attach() {
            // 你的应用每产生一段 AI 正文，就推一次事件
            MyApp.on('assistantMessage', (text) => emit('message-received', { args: [text] }));
            MyApp.on('conversationSwitched', () => emit('chat-changed', {}));
        },
        detach() { },

        onEvent(type, handler) {
            if (!listeners.has(type)) listeners.set(type, new Set());
            listeners.get(type).add(handler);
            return () => listeners.get(type)?.delete(handler);
        },

        // 存档：没有原生位置就用 localStorage
        loadSettings: () => JSON.parse(localStorage.getItem('event-timer.settings') || 'null'),
        saveSettings: (s) => (localStorage.setItem('event-timer.settings', JSON.stringify(s)), true),
        loadChatState: () => JSON.parse(localStorage.getItem(`event-timer.chat.${MyApp.conversationId}`) || 'null'),
        saveChatState: (s) => (localStorage.setItem(`event-timer.chat.${MyApp.conversationId}`, JSON.stringify(s)), true),
        getChatId: () => String(MyApp.conversationId),

        getChatMessages: () => MyApp.messages.map((m, i) => ({
            index: i, text: m.content, isUser: m.role === 'user', isSystem: m.role === 'system', name: m.author ?? '',
        })),

        // 没有隐形注入能力 → 返回 false，App 会自动降级为「只在面板显示」
        setInjection: () => false,
        clearInjection: () => true,
        getInjection: () => '',

        getInputText: () => MyApp.input.value,
        setInputText: (t) => ((MyApp.input.value = t), true),
        appendToInput(t) { MyApp.input.value = MyApp.input.value.trim() ? `${MyApp.input.value}\n\n${t}` : t; return true; },
        focusInput: () => MyApp.input.focus(),
        toast: (msg) => MyApp.notify(msg),
    };
}
```

然后装配：

```js
import { TimerApp } from '../event-timer/app.js';
import { FloatingUI } from '../event-timer/ui/floating.js';

const app = new TimerApp({ host: createMyAppHost() });
await app.init();
new FloatingUI(app).mount(document.body);

// 关键：把提醒交给你的应用
MyApp.on('beforeSend', () => {
    const reminder = app.getApi().commit();     // 取提醒并记为「已提醒」
    if (reminder) MyApp.setSystemContext(reminder);   // 塞进你的 system prompt
});
```

**就这样。** 悬浮按钮、面板、设置、时间解析、事件调度全部直接复用。

## 三、三种「注入」思路（按能力从高到低）

| 你的应用能做什么 | 对应做法 | 体验 |
| --- | --- | --- |
| 能在拼 prompt 时插入一段隐藏文本 | `setInjection()` 返回 `true` | 和酒馆里一样，完全无感 |
| 只能改用户发出的消息 / 有一个「系统提示」输入框 | `setInjection()` 返回 `false`，改用 `window.StoryTimer.commit()` 手动拼进请求 | 需要几行胶水代码，效果一样 |
| 什么都改不了 | `setInjection()` 返回 `false` + 面板上点「复制到输入框」/「复制提醒」 | 全手动，但可用 |

第三种其实就是本插件在**老版本酒馆**上的降级形态。

## 四、DOM 监听方式（对付纯网页应用）

如果那个应用连 API 都不给，但正文渲染在 DOM 上，可以用通用宿主自带的监听器：

```js
import { createGenericHost } from '../event-timer/host/generic.js';
import { TimerApp } from '../event-timer/app.js';
import { FloatingUI } from '../event-timer/ui/floating.js';

const host = createGenericHost({ chatKey: 'other-app' });
const app = new TimerApp({ host });
await app.init();
new FloatingUI(app).mount(document.body);

// 指定「消息容器」和「单条 AI 消息」的选择器即可
host.attachDomWatcher({
    container: '#chat-list',
    message: '.message.assistant',
    userMessage: '.message.user',
});
```

`MutationObserver` 只处理**第一次见到**的节点（用 `WeakSet` 记过），
所以不会重复喂同一段正文。

同样的能力在酒馆之外可以做成用户脚本（Tampermonkey 等），
把上面这段塞进 `document-idle` 时机即可。要点：

- 用户脚本里 `import` 不能用相对路径，需要你把 `event-timer/` 目录里的文件打包成单文件；
  或者用 `import()` 指向一个你自己托管的 HTTPS 地址；
- 如果那个应用的界面是 iframe，记得在正确的 document 上 `mount`；
- 悬浮面板的 `z-index` 是 `30000`，如果被其它浮层盖住，可以在自己的 CSS 里再提一层。

## 五、只想复用解析能力？

如果你不需要界面，只想要「从一段正文里抽出时间和事件」这个能力，
直接引核心就行，完全没有依赖：

```js
import { TimerEngine } from './event-timer/core/engine.js';

const engine = new TimerEngine({
    initialClock: { day: 1, minute: 8 * 60 },
});

// 喂一段 AI 正文
engine.observeMessage(aiText);

// 看当前状态
engine.clock;                       // { day: 3, minute: 870 }
engine.snapshot();                  // { clock, active, due, finished, nextDueMinutes }
engine.dueEvents;                   // 已经到点、等待交代的事件

// 取要注入的提醒文本
const reminder = engine.buildAndCommitInjection().text;
```

`core/` 里的三个文件都是零依赖的普通 ES 模块，也能直接在浏览器 `<script type="module">` 里用：

```html
<script type="module">
  import { TimerEngine } from '/path/to/event-timer/core/engine.js';
  // ...
</script>
```

## 六、移植时最容易踩的坑

1. **不要缓存 `getChatMessages()` 的返回数组**，每次现取。App 已经在需要的时候调用它。
2. **消息下标必须稳定**。App 用下标作为 `sourceIndex` 写进事件里做调试；
   如果你的应用会插入/删除消息，每次变动后推一次 `chat-changed`，App 会自动全量重放。
3. **`saveChatState` 要跟着聊天走**。如果所有聊天共用一个 localStorage key，
   换聊天时状态会串味。至少用 `chatId` 拼进 key 里。
4. **`toast` 不要抛异常**。App 里到处都在调它，抛了就中断流程。
5. **`onEvent` 必须返回取消订阅函数**，否则热重载时会重复注册，一次消息处理好几遍。
6. **时间推进的语义**：如果你的应用里 AI 一次回复可能包含多段（比如群聊里多个角色），
   把它们**顺序**喂给同一个 App 实例即可 —— 引擎是按轮次线性推进的。
